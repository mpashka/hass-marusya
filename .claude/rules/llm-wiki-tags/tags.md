# llm-wiki-tags — тэги

**Тэг** — короткий slug в kebab-case, записанный токеном `@tag:<slug>`. Один и
тот же токен ставится **и в коде, и в документации**, поэтому один поиск находит
все места, где живёт концепт, независимо от дерева директорий. Соседние правила:
[`wiki.md`](wiki.md), [`docs-layout.md`](docs-layout.md).

## Формат

- **Slug**: `[a-z0-9-]+`, при желании **иерархический** через `/` —
  `@tag:payments`, `@tag:payments/retry`. Иерархия предпочтительна: поиск по
  родителю находит и всех потомков, а иерархия повторяет дерево документации.
- **Документация** (`.md`): YAML front matter в начале файла, поле `tags` со
  списком токенов через пробел; для директории — в её `index.md`.
  ```
  ---
  tags: "@tag:payments @tag:payments/retry"
  ---
  ```
  Тэг, относящийся к одному разделу, ставится вместо этого строкой
  `@tag:<slug>` в теле рядом с этим разделом.
- **Код**: токен в комментарии прямо над маркируемым элементом — пакетом,
  файлом, классом (или аналогом) либо методом/функцией. Особенности языков — в
  правилах `code-tags-*.md` рядом с этим файлом.
- **Несколько тэгов**: через пробел — `@tag:ui @tag:mechanism`.
- Всегда сохраняй именно токен `@tag:<slug>`: голый список slug'ов не ищется.

## Реестр

Каждый тэг один раз регистрируется в `docs/tags.md` с однострочным описанием
связываемого концепта. Регистрируй тэг до того, как поставишь его, и держи реестр
в актуальном состоянии, когда тэги добавляются, переименовываются или выводятся
из обращения. Если концепт — ещё и термин словаря, описание ссылается на его
строку в `docs/terms.md`, а не определяет заново (см. [`glossary.md`](glossary.md)).

**Не** выдумывай тэги под разовые детали: тэг — для сквозного концепта,
повторяющегося в коде и документации.

## Поиск

```bash
grep -rn "@tag:payments" .                     # все места тэга (и его потомков)
grep -oE "@tag:[a-z0-9/-]+" path/to/file       # тэги одного файла
grep -rhoE "@tag:[a-z0-9/-]+" . | sort -u      # все тэги репозитория
```
